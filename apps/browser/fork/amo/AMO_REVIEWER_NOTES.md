# AMO reviewer notes

## Purpose

Vaultwarden Companion is an unofficial Firefox password manager client intended for a user-selected
self-hosted Vaultwarden server.

## Test steps

1. Install the submitted XPI in Firefox 142 or newer.
2. Open the toolbar action and confirm that the Self-hosted server dialog opens automatically.
3. Enter a test Vaultwarden server URL and sign in with a test account. If you cancel setup first,
   Self-hosted remains selected and requests fail against `self-hosted.invalid`.
4. Synchronize the vault, open one login, edit a non-sensitive test field, and save it.
5. Open a matching test website and confirm that the extension offers and fills the test login.
6. Lock the vault, unlock it again, and confirm that the saved change remains available.

## Permissions and data

The broad page and host permissions are required for a password manager to detect login fields,
match saved website URLs, save logins, and fill credentials across user-selected websites. The
remaining API permissions support storage, clipboard actions, context menus, idle locking,
navigation and request handling, notifications, and optional native-app or Firefox privacy
integration.

The extension transmits encrypted account and vault data to the account server selected by the
user. It can also use the feature-specific destinations documented in `PRIVACY.md`. The manifest
declares the Firefox data categories for authentication, browsing, financial, communication,
identity, website-content, and website-activity data. Firefox 142 is the minimum version so the
built-in consent prompt is available on both desktop and Android builds of Gecko.

## Build

The submitted package is generated by Webpack and Terser from TypeScript, Angular templates, local
assets, and the dependencies locked in `package-lock.json`. Human-readable source is attached.

Use Node 24.17 or newer and npm 11:

```sh
npm ci
npm --workspace @bitwarden/browser run release:check:fork:firefox
```

The release command runs focused fork compatibility tests, the common legacy cipher regression,
targeted verification, creates the production Manifest V2 build, validates the fork identity, and
runs `web-ext lint` in one flow. The current upstream cross-browser bundle reports 75 reviewed
warnings: 27 uses of `eval` or `Function` in bundled dependencies, 10 dynamic `innerHTML`
assignments in the Angular/autofill runtime, and 38 references to APIs used only by other browser
branches. The release gate fails on any lint error or any change to that exact warning inventory. It
writes the XPI, source archive, hashes, and release manifest under `apps/browser/dist/release/`.
The release manifest records the Git commit and whether the working tree is clean. AMO signing is
blocked when the tree is dirty; local dirty preflight runs are still allowed for testing.

The OSS browser build excludes `bitwarden_license`. Root license files and third-party notices are
included in the source archive. Original fork artwork is identified separately in
`apps/browser/fork/icons/README.md`.
